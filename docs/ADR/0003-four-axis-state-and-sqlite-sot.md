# ADR-0003：SQLite 单一业务真相源与四轴分离状态模型

- **状态**：已采纳（M0 基线）
- **日期**：2026-11-24

## 背景
商业客户端采用“本地 `tasks.json`（仅保留最近 150 条消息）+ 远端业务后端”双副本模型，并且将单轮执行完成、主要填写完成（含计费事件）、按钮点击与官网提交成功混杂在不同层的状态字段中，容易在断网、重启或超时后产生状态漂移甚至重复投递风险。

## 决策
1. **SQLite 作为唯一业务真相源（SoT）**：采用 Node/Electron 内置 **`node:sqlite`**（`DatabaseSync`，零原生 C++ 编译依赖），任务、运行轮次、有序事件流（不设 150 条截断）、问题卡、核对授权卡、有副作用动作账本、档案不可变版本快照与本地求职进度均通过 ACID 事务持久化。
2. **模型会话上下文与业务状态解耦**：模型上下文仅服务于推理续接，绝不作为数据库业务状态来源；UI 完全由数据库状态与有序事件流投影。
3. **四轴分离状态模型**：所有投递任务独立存储 `executionState`、`waitingReason`、`applicationStage`、`outcome`，并通过数据库 `CHECK` 约束与状态机服务双重校验。
4. **凭据物理隔离**：模型 API Key 仅存于 Electron `safeStorage`（Windows DPAPI），SQLite 只保存 `credentialKey` 引用名。

## 权衡与后果
- **收益**：彻底根除“只读观察结束被当成已投递”“重启丢消息”“切换默认档案污染旧任务”等架构隐患；支持完整本地审计与脱敏导出。
- **代价**：需要在 M1 引入规范的 SQLite 迁移框架与事务封装，并在写操作前遵循“先落账、再执行、后回写”纪律。
